## Question and decision

Can a contextualizer learn **how far information from each visible motion unit should propagate**, improving unsupervised action segmentation beyond choosing one temporal scale for a whole dataset or chunk? The first experiment isolates contextual aggregation. The tokenizer and OT decoder stay fixed so that a paired difference among the new arms tests the attention mechanism, subject to optimization variability.

The central comparison is **unit-conditioned versus chunk-level support**. An equal-weight support model and a model without the new attention prior are necessary controls. Existing fixed-mask contextualizers are historical performance references. This phase does not claim that its learned support identifies the true duration of an action: context range, training mask span and decoded action duration are different quantities.

## Evidence motivating the test

Phase 6 reported T2 relational tokens at mask span 2 versus 8: BABEL-2 **29.39 versus 21.43** F1@50 and BABEL-3 **23.86 versus 18.56** (five seeds); LARa **24.02 versus 19.09** (three seeds). HuGaDB raw tokens moved the other way, **39.90 versus 46.23**. On BABEL-3, shortening the mask **did not help** raw tokens (−1.38, within the declared 3-point bar) but helped relational tokens. These results establish sensitivity to tokenizer and training scale, not that a learned scale will help. The earlier ground-truth-duration threshold is unsupported by LARa and must not select a Phase 7a setting.

Phase 7 then found on BABEL-1: T2/span 2 beats original T0/span 8 by **14.15** F1@50 and T2 `centre` by **4.99** over the three original seeds, while its **+2.10** over T2/span 8 does not pass the span bar. Phase 7's cross-seed stability selector K1 picked an acceptable fixed span on all five datasets in a **retrospective screen**; K3 and K4 failed. This raises the bar for Phase 7a: a fixed span selected without labels is already a plausible competitor. BABEL-1 remains a previously analysed dataset with ten byte-identical recordings overlapping BABEL-2/3; it is not an independent test set.

The contribution target is narrower than variable-length segments in general: [A4Mer](https://arxiv.org/html/2604.28173v1) already learns variable-length atoms and motifs, and [D-CLOT](https://arxiv.org/html/2608.05877v1) already feeds transport assignments back into representation/prototype refinement. Phase 7a tests whether **the temporal support used to compose fine motion tokens** should vary within a recording. Strong results would motivate a subsequent joint contextualizer/transport method; originality and advantage over those papers still require direct comparison.

## Fixed inputs and decoder

BABEL-1 reuses the verified Phase 7 T2 preparations if its optional stage runs; it must not require Phase 7 to be rerun.
- Use the existing `context_id` input embedding, 128-wide, four-layer, four-head, feed-forward 512, post-LayerNorm transformer, ALiBi and dropout 0.1. Context length 128 tokens, stride 64, batch 64, 5,000 accepted updates, learning rate 3e-4 with 500-step warmup and the existing cosine schedule. **The validation-loss-selected checkpoint is primary**, matching Phases 5–7; step 5,000 is secondary. On BABEL-2/3, Phase 5/6 selected steps 400–1,100 and the median final/minimum validation-loss ratio was approximately 1.20–1.28, so the final checkpoint is not a sound primary comparison. Use the same label-free validation rule for every new arm; do not choose a checkpoint by segmentation score.
- Keep the existing 30% masking fraction and code-ID cross-entropy on eligible targets. Alternate requested mask spans **2 and 8** on successive accepted updates, starting with 2; use separate deterministic mask streams. If a proposed batch has no eligible targets, retry under the existing empty-batch policy without advancing the alternation. All arms see the same chunks, span sequence, mask indices, training segments and update count within a dataset/seed. Record accepted updates, eligible targets and real-frame weights separately for each span. No action labels enter training or checkpoint selection.
- At inference use unmasked code sequences. Average overlapping chunk embeddings and L2-normalize as in Phase 5. Fit and score the **unchanged** pooled continuous-cosine OT procedure: same initial grouping, state count, coefficients, radius, outer cap 50 and 500/1,000/2,000/4,000 continuation rungs. Save frame predictions and OT traces. Action labels enter only scoring and interpretation; the known dataset action-class count remains an existing protocol assumption.
- Train on the available RTX 4090 and decode OT on CPU, with the existing numerical-thread cap. Run jobs sequentially so timing and deadline decisions remain inspectable.

## One new mechanism, four arms

The first transformer layer uses ALiBi attention within a **fixed radius of 4 tokens** in every new arm. In layers 2–4, a gate on each **visible source token** supplies three nonnegative weights that sum to one for attention ranges **4, 16 and 127 tokens**. The last range covers the whole 128-token chunk. For valid query *t* and key *j*, define

`prior(t,j) = sum_s gate(j,s) * 1[|t-j| <= radius_s] / count_valid_keys(t,s)`.

Add `log(prior(t,j))` to the existing ALiBi attention logits and mask padded keys. The last range and softmax gate make the prior positive for every valid key. Use the same prior in all heads; calculate its range counts using each chunk's valid length, never its padded length. A **visible key** is gated from its own code embedding, before contextual layers. A masked key gets a fixed uniform gate with no gate-network gradient; the hidden code at a target is unavailable to its gate. Thus the trainable gate only encounters visible code embeddings in training, as it does at inference, and cannot read whether its own token was masked or infer the requested span from its gate input. Masked keys remain in attention as in the existing model. The effective receptive field includes the first layer's four-token radius; the three range values describe **later-layer attention support**, not exact end-to-end reach. Save gate values at every unmasked inference token, averaged over overlapping chunks with the same weights used for embeddings. OT's temporal neighbourhood remains unchanged.

| Arm | Gate input and support choice | Role |
|---|---|
| `unit_gate` | The visible source token's code embedding; one range mix per visible code occurrence. Mask-token keys receive a fixed uniform mix. | Proposed method: vary how far each unit can contribute. |
| `chunk_gate` | Mean embedding of **visible** code tokens in the chunk; the same mix at every position. Uses the **same gate network and trainable parameter count**. | Primary control for code-specific support within a chunk. |
| `uniform` | Exactly one-third weight for each range; same backbone and attention calculation, with no trained gate. | Simple multiscale control; disclose the small parameter-count difference. |
| `no_prior` | The same fixed-radius first layer and mixed-mask training, but layers 2–4 use ordinary ALiBi without the new range prior. | Tests whether the multiscale attention prior helps at all. |

The gate is a 128→64→3 MLP with GELU and softmax, no gate dropout. Initialize its final linear weights and bias to zero so both learned gates start at uniform support. Match backbone, input embedding and prediction-head initialization within each seed. Isolate initialization and training RNG streams so a change in arm does not silently change masks, batch order or dropout. The `uniform` and `no_prior` arms omit the unused MLP but retain the identical backbone and head; record total and trainable parameter counts. The gate should depend only on the source unit's embedding, not on its first-layer state, because first-layer states at masked targets expose the span pattern during training.

The gate is trained by the **same masked-code prediction loss** as the contextualizer. There is no OT gradient or ground-truth duration input. Random masks still alter which *other* tokens the contextualizer sees, but the gate's direct input distribution is the distribution of visible code IDs in both training and inference. A gate can still settle on one range everywhere, or learn a code-specific shortcut that helps prediction without improving action discovery; those are measured failure modes. Unit-conditioned support is weaker than a boundary-aware temporal model: identical codes get the same gate before downstream attention, and this limit must be disclosed.

## Reading rules

Primary metric: pooled global-mapping F1@50 at OT rung 4,000, **validation-selected checkpoint**, paired by seed. Validation uses masked-code loss without action labels, with a fixed 50/50 span-2/span-8 mixture and identical validation masks for every arm. Save the final step-5,000 checkpoint and its validation and segmentation scores as a secondary sensitivity. Also report MoF, Edit, F1@10/25, predicted and ground-truth run counts, and scores stratified by ground-truth segment duration. Seed SD describes initialization sensitivity, not sampling uncertainty. Do not tune on these evaluation labels.

- **Mechanism test (BABEL-2/3):** `unit_gate − chunk_gate`, paired by seed. A promising Phase 7a result requires a ≥3-point mean F1@50 gain with all three paired differences positive on **each** BABEL dataset, no ≥3-point MoF loss, and a ≥1-point mean loss from replacing unit gates by recording-mean gates in stage 1b with at least two of three seeds positive on each dataset. This is an engineering decision rule, not a significance test. Also report `unit_gate − uniform` and `unit_gate − no_prior`; if the unit gate fails to beat either of these in mean F1@50 on both datasets, do not claim the learned multiscale prior improves segmentation.
- **Competitiveness:** compare the new arms with the declared **K1-selected fixed-span** context references on the **same three seeds**: BABEL-2 T2/span 2 **30.68**, BABEL-3 T2/span 2 **23.23**, LARa T2/span 2 **24.02**, HuGaDB T0/span 8 **46.23** F1@50. BABEL-1's K1 pick is T2/span 8; use exactly the three common original seeds for its comparison. K1 passed only a retrospective selector screen, and the new models use a mixed-span training objective, so the performance comparisons are contextual rather than single-factor ablations. No evaluation label may select a new phase setting.
- **Within-recording variation:** report gate entropy, mean weights, fraction of positions dominated by one range, within-recording weight variation and gate changes near annotated boundaries. Report gate distributions on visible training keys under each mask span and on unmasked inference keys. The boundary and duration analyses are post-hoc diagnostics. On **every BABEL-2/3 `unit_gate` cell**, decode the same selected checkpoint with its gates replaced at inference by that recording's mean gate and by one-third weights. These are diagnostic ablations, not independently trained controls. If the learned gate is essentially constant or replacing it with its recording mean leaves predictions unchanged, do not call the result within-recording adaptation. An improved selected score with a much worse 5,000-step endpoint should be reported as checkpoint sensitivity.
- **External dataset checks:** report LARa, HuGaDB and BABEL-1 separately with the same fixed settings. In particular, a BABEL gain and HuGaDB loss would constrain the scope of the proposed mechanism. Do not describe BABEL-1 as independent data, or HuGaDB's IMU and BABEL/LARa's pose results as interchangeable.

Interpretation requires both the paired architectural control and the fixed-span performance reference. A positive Phase 7a result would justify **testing whether the learned temporal affinities should also guide OT** in a later phase. It would not yet establish reusable movemes, correct action boundaries, state-of-the-art performance, or novelty over prior variable-duration representations. No inference about those claims should be made from gate visualizations alone.
